# Compatibility and updates

Initial baseline: OpenClaw **2026.11.6**, tag `v2026.11.6`, commit `06afb10d3272cc9deaf38ca6a3b7b839d5935638`. Linux serving through `gateway.controlUi.root`; separate local static build. The Control UI shares upstream routes, permissions, transport, output renderer, queue and approval controllers.

Do not upgrade the Gateway to install this skill. `check-update` compares the local CLI version with the recorded baseline and returns exit 2 when unverified. Confirm the CLI belongs to the running service: `openclaw --profile PROFILE gateway status --deep`, and inspect the browser's version. A local CLI check alone is not proof of the running Gateway. The UI adapter additionally checks its connected host version where available.

Run `off` before upgrading OpenClaw. This restores the previously configured root; if that original root is another custom UI, its owner must also verify compatibility. If the host auto-updates with LazyKins enabled, the UI must stop its custom presentation on a mismatch and show an actionable notice. Use shell `off` even when the browser cannot boot. No automatic engine upgrades, hidden polling, model turns to poll versions, or remote repair downloads.

For future releases, obtain a separate clean matching tagged source checkout with its own lockfile/toolchain. Review and refresh the narrow runtime patch. Refuse ambiguous changes; never fuzzy-patch production bundles. Rebuild, verify assets and auth/streaming/Stop/approvals/reconnect/route transitions, inspect responsive light/dark screenshots, and test both skills' ownership-preserving rollback. Record exact SHA, integration and tested versions in a new payload manifest. Publish a new immutable generation and keep the previous build. Update the controller's allowed baseline only after these checks pass.

The shipped controls use supported config commands, preserving JSON5, includes and secret references. Set and restoration to a previous value use native conditional expectations. Restoring a previously absent root uses a conditional write of the current `gateway.controlUi` parent with only `root` removed. It refuses credential-bearing parents because `config get` redacts credentials. In that case pause administrative changes, inspect ownership and use a supervised native `config unset gateway.controlUi.root`; preserve the LazyKins receipt until verified. Native conditional expectations can also refuse included/redirected paths rather than retargeting writes. Never fall back to an unconditional automated unset or replace redacted credentials.

Before concluding an install, inspect `openclaw skills info lazykins --agent AGENT --json` and `sanitize`, check allowlists/readiness, then test actual ordinary invocation. Local folder installation follows native security policy. If blocked, report the policy decision; do not bypass it.
