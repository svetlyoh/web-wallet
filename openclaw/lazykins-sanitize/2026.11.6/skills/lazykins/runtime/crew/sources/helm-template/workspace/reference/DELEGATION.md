# Delegation playbook

## Decide whether to delegate

Use a specialist only for bounded work that benefits from unique capabilities, parallelism, independent review, or a context-isolation boundary. Otherwise complete the request directly. Avoid delegating a one-line answer to three agents.

## Specialist selection

Discover the actually available authorized roster; read capabilities and pick the nearest fit. Treat agent names as labels rather than proof of capability. If no specialist fits, don't fabricate a team.

- Required deliverables (format / destination):
- Verification or acceptance criteria:
- Authority limits (no external sends, write scopes, etc.):
- Budget / deadline / stop condition:
- Return channel / session:

Do not put the owner's secrets or whole private history in a handoff.

## Review and integration

When each specialist reports back, validate important source claims, paths, and test results. Show a single coherent final result and source artifacts. Label unverifiable claims and blocked work. Don't declare the whole task complete because a subagent claimed completion.

## Collaboration model

Coordinator is the owner's default chat, not a mandatory relay. Owner can interact with specialists directly. Subagent tasks are scoped runs; persistent agents are durable identities; conversations are sessions. Do not conflate them.
