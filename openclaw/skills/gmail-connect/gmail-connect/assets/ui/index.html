Prepare your Google project

One-time setup in your own Google account. No Google Cloud CLI needed.

New to Google Cloud?

Create one private project for this connection. Gmail API access does not normally require billing.

Show every project-creation step
  1. Sign in to Google with the Gmail account you intend to connect.
  2. Click Create Google project below.
  3. For Project name, enter something recognizable such as OpenClaw Gmail.
  4. Optionally edit the Project ID. Google generates one automatically and it cannot be changed later.
  5. For personal Gmail, leave Location as No organization when available. Workspace users should select an organization their administrator permits.
  6. Click Create, wait for completion, then use Google Cloud’s project selector to select the new project.
  7. Copy the exact Project ID into the field on this page. Do not use the display name or project number.

Open this project ↗
  1. Enable Gmail API ↗

    Check the project name in Google’s top bar. Click Enable; if the page says Manage, it is already enabled.

    Show Gmail API steps
    1. Enter the Project ID above first, then open the Gmail API link.
    2. Confirm the intended project is selected in Google Cloud’s top bar.
    3. Click Enable and wait for the API overview page. Do not create an API key.
    4. If Google shows Manage or an API metrics page, this step is complete.
  2. Configure Google Auth Platform ↗

    Set the app name and audience, add your account as a test user when External, and declare only the Gmail access you need.

    Show Branding, Audience, and Data Access steps
    1. Open Google Auth Platform. If it says Not configured yet, click Get started.
    2. Under App Information, name the app OpenClaw Gmail Connect, choose your support email, and click Next.
    3. Under Audience, personal Gmail users choose External. Internal is only for an eligible Google Workspace organization. Click Next.
    4. Under Contact Information, enter your email and click Next.
    5. Under Finish, review Google’s User Data Policy, select I agree if you accept it, click Continue, then click Create.
    6. If External and in Testing, open Audience → Test users → Add users, enter the exact Gmail account you will authorize, and save it.
    7. Open Data Access → Add or Remove Scopes. Select https://www.googleapis.com/auth/gmail.readonly. Select https://www.googleapis.com/auth/gmail.send only if you will enable reviewed sending in Step 2, then click Update or Save as shown.
    Open Audience ↗Open Data Access ↗Google’s consent guide ↗

    External apps in Testing can lose Gmail refresh tokens after 7 days. For longer use, review Google’s Production and verification requirements. Workspace policy can still require administrator approval.

  3. Create a Desktop OAuth client ↗

    Create a Desktop app client and download its JSON file. Do not create a web client, API key, or service account.

    Show Desktop client steps
    1. Open Google Auth Platform → Clients.
    2. Click Create client.
    3. Choose application type Desktop app.
    4. Name it OpenClaw Gmail Connect and click Create.
    5. Click Download JSON. Keep the file private; you will upload it locally in Step 2.
    6. No redirect URI needs to be entered manually for a Desktop app.

2

Authorize your account

Your password is entered only on Google’s website.

Show account authorization steps
  1. Upload the Desktop app JSON from Step 1. A successful upload changes the notice above to Credentials imported.
  2. Leave sending unchecked for read-only access. Check it only if you also added Gmail send in Data Access.
  3. Click Connect with Google. A new Google tab opens.
  4. Select the same Gmail account used as the External test user. Check that Google shows your own project/app name.
  5. Review the requested permission and continue. If Google says Access blocked, read its reason: add the account under Audience only when Google says it is not a test user; check the selected project/client for a mismatch; or contact the Workspace administrator when an organization policy blocks access. Do not disable browser security or share the credential file.
  6. After the Gmail connected page appears, close that Google tab, return here, and click Refresh status.
  7. Confirm the account shown in Step 3 is the mailbox you intended.
Using a browser on another computer over SSH?

Run this on the computer with the browser, replacing the two placeholders:

ssh -N -L 8766:127.0.0.1:8766 YOUR_USER@YOUR_UBUNTU_HOST

On Ubuntu, start this wizard with --no-browser, then open its private 127.0.0.1:8766 link in the forwarded computer’s browser. Keep both processes running until Google returns to Gmail Connect. Never bind the wizard to 0.0.0.0.

A browser on this Ubuntu desktop is simplest (NoMachine works). A loopback callback on the wrong computer cannot finish setup without the SSH forward.

3

Check the connection

Verify real Gmail access before enabling background checks.

Show verification and background-check steps
  1. Confirm the Account below is the Gmail address you intended.
  2. Click Verify Gmail. This checks the Gmail profile and performs the first mailbox synchronization; it does not send mail.
  3. Look for the success notice and a time under Last mailbox sync.
  4. Optionally click Enable background checks. This creates only the separate openclaw-gmail-connect.service user service and does not edit or restart the OpenClaw gateway.
  5. Continue to Step 4 and search for a known message. This separately confirms that mail content is available.
  6. Start a new OpenClaw chat and ask: Use Gmail Connect to show my five newest inbox messages.

Background checks update a local feed about once a minute while this computer is awake. Your OpenClaw agent can read it using the skill. Automatic Telegram messages require a separately configured OpenClaw heartbeat or automation.

Keep checking after logout or a cold boot

User services normally start with your login. For unattended operation, run this one administrator command in your Ubuntu terminal:

sudo loginctl enable-linger "$USER"

This keeps your user’s services available. It does not prevent sleep or start OpenClaw’s gateway.

Need immediate push notifications?

This version uses direct Gmail polling. Native OpenClaw Pub/Sub with Tailscale Funnel is an advanced alternative covered in references/native-push.md. It is not activated by this wizard.
